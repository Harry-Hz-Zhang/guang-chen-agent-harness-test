# Spec — memory

## Purpose

定义长期记忆的存储形态（MEMORY.md 索引 + 细碎条目文件）、写入去重、低频合并、闲置会话自动总结，以及记忆在上下文中的召回时机与放置方式。

## ADDED Requirements

### Requirement: 记忆存储形态

长期记忆 SHALL 按会话隔离存储于本地目录：每个会话一个记忆目录，含 MEMORY.md（全部记忆条目的索引）与若干条目文件（单条记忆正文，frontmatter 含内容哈希、创建时间、标签）。

#### Scenario: 目录结构

- **WHEN** 会话 s1 生成第一条记忆
- **THEN** 出现 s1 的记忆目录，MEMORY.md 含该条目索引，条目文件 frontmatter 含哈希与时间

### Requirement: 写入哈希去重

写入记忆时系统 SHALL 对规范化后的内容计算 SHA-256，已存在相同哈希的条目时跳过写入（不新增文件、不重复索引）。

#### Scenario: 完全相同内容写两次

- **WHEN** 同一会话先后写入两条完全相同的记忆内容
- **THEN** 条目文件数量不变，第二次写入被跳过

#### Scenario: 内容不同正常写入

- **WHEN** 写入内容不同的记忆
- **THEN** 新条目文件生成，索引更新

### Requirement: 低频 LLM 合并

系统 SHALL 支持对记忆条目执行 LLM 合并：以现有条目与新条目为输入，LLM 输出 ADD / UPDATE / DELETE / NOOP 四类动作，系统按动作应用后重写 MEMORY.md 索引。合并 MUST NOT 使用 embedding 或向量检索。

#### Scenario: 合并去重改写

- **WHEN** 合并时 LLM 判定新条目与旧条目 A 语义重复且信息更全
- **THEN** 旧条目 A 被更新（或删除新增），索引重写后不残留被删条目

### Requirement: 闲置会话后台总结

后台任务 SHALL 周期性（默认每 5 分钟）扫描全部会话文件：最后修改时间超过闲置阈值（默认 2 小时）且尚未生成过记忆的会话，SHALL 自动调用 LLM 总结该会话并写入其记忆目录。判定与周期均可配置。总结失败 SHALL 不阻塞扫描（下轮扫描自然重试），活跃会话 MUST NOT 被总结。

#### Scenario: 闲置会话被总结

- **WHEN** 闲置阈值配置为 3 秒，某会话 3 秒未更新且扫描周期到达
- **THEN** 该会话的记忆目录生成 MEMORY.md 与总结条目

#### Scenario: 活跃会话不被总结

- **WHEN** 会话仍在对话中（最后修改时间早于闲置阈值）
- **THEN** 扫描跳过该会话，不生成记忆

#### Scenario: 已总结过不重复总结

- **WHEN** 会话已生成过记忆且无新消息
- **THEN** 后续扫描不再重复总结该会话

### Requirement: 记忆召回时机与放置方式

记忆的召回时机为「组装上下文时」：若该会话记忆目录存在，系统 SHALL 把记忆摘要渲染为系统提示词的附加段注入。会话内多轮请求共享同一份召回结果（该次运行开始时加载）。

#### Scenario: 召回注入系统提示词

- **WHEN** 会话已有记忆文件，用户新开一轮对话
- **THEN** 发送给 LLM 的系统提示词包含「历史记忆」段，内容来自 MEMORY.md
