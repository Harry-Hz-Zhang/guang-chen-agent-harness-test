# Spec — context

## Purpose

定义发送给 LLM 的上下文如何组装（系统提示词、记忆、摘要、历史、当前输入）以及超长上下文的基础压缩行为（触发条件、压缩方式、保留策略）。

## ADDED Requirements

### Requirement: 上下文组装

发送给 LLM 的消息列表 SHALL 按以下顺序组装：系统提示词（含该会话的长期记忆摘要段，如有）→ 压缩摘要消息（如有，替代最早的被压缩区间）→ 未压缩的历史消息（其尾部为最近 5 轮对话原文，见「压缩保留最近 5 轮原文」）→ 当前用户输入。组装结果 MUST 保持 tool 调用与工具结果消息成对完整。

#### Scenario: 注入长期记忆

- **WHEN** 该会话存在已生成的长期记忆文件
- **THEN** 组装出的消息列表中系统提示词包含记忆摘要段

#### Scenario: 摘要消息带明确标记

- **WHEN** 会话存在压缩记录，组装上下文
- **THEN** 摘要以 `name="__compaction_summary__"` 的独立消息形式插入，且其 content 首行含明文标记「以下为此前对话的压缩摘要」，使 LLM 能区分摘要与原文

#### Scenario: 摘要替代被压缩历史

- **WHEN** 会话存在压缩记录（被压缩区间为序号 0-29）
- **THEN** 组装结果不包含序号 0-29 的原始消息，取而代之的是压缩摘要消息与序号 30 之后的历史

### Requirement: 压缩触发条件

系统 SHALL 在「会话累计对话轮数达到阈值（默认 60）」或「估算 token 达到阈值（默认 100K）」任一满足时触发压缩，两个阈值均可配置。术语区分：「对话轮」指会话中一次完整的用户输入与该输入引发的最终 assistant 回复（一对 user/assistant，追加轮以 user 消息数计）；与 agent-loop 的「单次请求决策轮」无关。**轮数与 token 估算 SHALL 均以「尚未被压缩的消息区间」为统计口径**（已压缩区间不计入），以保证压缩后计数回落、不会每轮重复触发。token 估算 SHALL 使用字符近似（不依赖真实 tokenizer）。

#### Scenario: 轮次触发

- **WHEN** 轮次阈值配置为 5，会话累计对话轮数达到 5
- **THEN** 下一次 LLM 调用前触发压缩

#### Scenario: token 触发

- **WHEN** 估算 token 超过配置阈值（即使轮次未达）
- **THEN** 同样触发压缩

#### Scenario: 压缩后计数回落

- **WHEN** 刚完成一次压缩（未压缩区间内轮数/估算 token 均回落至阈值以下）
- **THEN** 下一次 LLM 调用前不重复触发压缩

### Requirement: 压缩保留最近 5 轮原文

压缩 SHALL 保留最近 5 轮对话（默认 `keep_recent_rounds=5`，即 10 条 user/assistant 消息）的消息原文不压缩，仅对更早的消息生成摘要。保留边界 SHALL 按「对话轮」边界切分，并连带保留被保留轮内的工具调用配对消息（assistant(tool_calls) 与 role=tool），故实际保留条数可多于 10 条。保留轮数可配置，最小值为 1。

#### Scenario: 保留 5 轮原文

- **WHEN** 会话已积累 5 轮纯对话（10 条消息）并触发压缩
- **THEN** 这 5 轮（即 10 条消息）不被压缩，仍以原文形式出现在返回结果中

#### Scenario: 保留轮内工具配对连带保留

- **WHEN** 第 4 轮包含一次工具调用（user / assistant(tool_calls) / tool / assistant 共 4 条）且触发压缩
- **THEN** 该轮的 4 条消息全部保留原文，且工具配对不残缺

（保留边界落在工具配对中间的情形，由下文「压缩不拆散工具调用对」统一约束）

### Requirement: 压缩行为

压缩 SHALL：① 保留最近 5 轮对话原文（见上一条 Requirement）；② 对更早的消息调用 LLM 生成 5 字段结构化摘要（任务概览 / 当前状态 / 重要发现 / 下一步 / 需保留的上下文）；③ 把压缩记录（区间 + 摘要）追加写入会话文件；④ 摘要消息在后续组装中替代被压缩区间。压缩失败 SHALL 降级为告警并继续原流程，MUST NOT 阻断主循环。

#### Scenario: 生成结构化摘要

- **WHEN** 触发压缩
- **THEN** 摘要包含任务概览 / 当前状态 / 重要发现 / 下一步 / 需保留的上下文五个字段

#### Scenario: 压缩后仍可答早期事实

- **WHEN** 压缩完成后用户追问被压缩区间的某个事实
- **THEN** 系统基于摘要仍能正确回答

#### Scenario: 压缩失败不阻断

- **WHEN** 摘要 LLM 调用抛出异常
- **THEN** 主循环记录告警并继续未压缩流程，用户请求正常完成

### Requirement: 压缩不拆散工具调用对

压缩的切分点 SHALL 保证任何 assistant 工具调用消息与其对应的 tool 结果消息要么同时保留、要么同时被压缩，MUST NOT 出现落单的半对。

#### Scenario: 切点落在配对中间

- **WHEN** 保留边界恰好切在「工具调用消息与其结果消息」之间
- **THEN** 切点自动回退到配对开始前，两条消息同侧
